=======================================================================================================================================================================
Architecture
=======================================================================================================================================================================
- Spring can integrate with JPA while Hibernate remains the JPA provider.
- JPA continues to define the persistence API and ORM concepts.
- Hibernate continues to implement the JPA specification.
- Spring primarily provides:
  - configuration and bootstrapping
  - dependency injection
  - EntityManager management
  - transaction management
  - integration between persistence and other application layers

Architecture:

    Application
         |
         v
    Spring
         |
         +----------------------+
         |                      |
         v                      v
    JPA Infrastructure      Transaction Management
         |
         v
    EntityManager
         |
         v
    JPA
         |
         v
    Hibernate
         |
         v
    Database


------------------------------------------------------------
JPA + Hibernate Without Spring
------------------------------------------------------------

- In a standalone JPA application, the application code is responsible for bootstrapping JPA.

Example:

    EntityManagerFactory emf =
        Persistence.createEntityManagerFactory("myPU");

    EntityManager em =
        emf.createEntityManager();

    EntityTransaction tx =
        em.getTransaction();

    tx.begin();

    em.persist(user);

    tx.commit();

    em.close();
    emf.close();

- persistence.xml contains the JPA persistence-unit configuration.
- The application explicitly creates the EntityManagerFactory.
- The application explicitly obtains the EntityManager.
- The application explicitly begins and commits the transaction.

Typical flow:

    persistence.xml
          |
          v
    Persistence Unit
          |
          v
    EntityManagerFactory
          |
          v
    EntityManager
          |
          v
    Hibernate
          |
          v
    Database


------------------------------------------------------------
JPA + Hibernate with Spring
------------------------------------------------------------

- Spring takes responsibility for configuring and managing the JPA infrastructure.
- The application generally does not need to manually create the EntityManagerFactory.
- EntityManager access is integrated with Spring's dependency injection and transaction management.
- Hibernate remains the JPA provider.

Typical flow:

    Spring Configuration
          |
          v
    EntityManagerFactory
          |
          v
    EntityManager
          |
          v
    Hibernate
          |
          v
    Database

- The persistence technology has not changed.
- The way the persistence infrastructure is created and managed has changed.

=======================================================================================================================================================================
Spring Configuration for JPA + Hibernate
=======================================================================================================================================================================

- Without Spring, JPA configuration is commonly defined through persistence.xml.

Example:

    <persistence-unit name="myPU">
        <provider>
            org.hibernate.jpa.HibernatePersistenceProvider
        </provider>

        <properties>
            ...
        </properties>
    </persistence-unit>

- With Spring, JPA infrastructure can be configured using Spring configuration.

Example:

    @Configuration
    @EnableTransactionManagement
    public class JpaConfig {

        @Bean
        public LocalContainerEntityManagerFactoryBean entityManagerFactory() {

            LocalContainerEntityManagerFactoryBean emf = new LocalContainerEntityManagerFactoryBean();

            // DataSource
            // entity package
            // JPA provider
            // JPA properties

            return emf;
        }

        @Bean
        public PlatformTransactionManager transactionManager(EntityManagerFactory emf) {

            return new JpaTransactionManager(emf);
        }
    }

- The exact configuration depends on the Spring version and application setup.
- The important concept is that Spring creates and manages the JPA infrastructure as Spring beans.

------------------------------------------------------------
EntityManagerFactory
------------------------------------------------------------

- EntityManagerFactory is still a JPA concept.
- Spring manages the EntityManagerFactory instead of application code manually creating it.

Without Spring:

    Persistence
        |
        v
    createEntityManagerFactory()
        |
        v
    EntityManagerFactory

With Spring:

    Spring ApplicationContext
        |
        v
    EntityManagerFactory Bean

- EntityManagerFactory is generally long-lived and shared by the application.
- It is not created for every database operation.

------------------------------------------------------------
EntityManager
------------------------------------------------------------

- EntityManager is still the standard JPA API used for persistence operations.

Example:

    entityManager.persist(user);

    entityManager.find(User.class, 10L);

    entityManager.remove(user);

- Spring integrates EntityManager with its transaction and dependency-injection infrastructure.
- Application code can receive an EntityManager through injection rather than manually creating one.

Example:

    @PersistenceContext
    private EntityManager entityManager;

- @PersistenceContext is a JPA annotation.
- In a Spring-managed application, Spring integrates this injection with the EntityManager lifecycle.

Important:

- Spring does not replace EntityManager with a completely different persistence API.
- The application can continue using the standard JPA EntityManager API.


------------------------------------------------------------
Transaction Management
------------------------------------------------------------

- One of the major benefits of integrating JPA with Spring is declarative transaction management.
- Without Spring, transaction boundaries can be managed manually.

Example:

    EntityTransaction tx = entityManager.getTransaction();

    tx.begin();

    entityManager.persist(user);

    tx.commit();

- With Spring, a transaction can be declared using @Transactional.

Example:

    @Transactional
    public void createUser(User user) {
        entityManager.persist(user);
    }

- Spring starts the transaction before the method executes.
- The method performs its persistence operations.
- Spring commits the transaction when the method completes successfully.
- If the transaction is rolled back, the persistence changes are not committed.

Conceptually:

    Method starts
         |
         v
    Begin Transaction
         |
         v
    EntityManager operations
         |
         v
    Method completes
         |
         v
    Commit Transaction

- @Transactional is provided by Spring's transaction management infrastructure.
- JPA itself does not provide the @Transactional annotation used here.


------------------------------------------------------------
JpaTransactionManager
------------------------------------------------------------

- JpaTransactionManager is Spring's transaction manager for JPA.
- It integrates Spring's transaction management with the JPA EntityManagerFactory.

Conceptually:

    @Transactional
          |
          v
    Spring Transaction Management
          |
          v
    JpaTransactionManager
          |
          v
    JPA EntityManager
          |
          v
    Hibernate
          |
          v
    Database

- It allows application code to use declarative transactions instead of manually controlling EntityTransaction.


------------------------------------------------------------
What Spring Changes
------------------------------------------------------------

- Spring changes how JPA/Hibernate is integrated into the application.

Without Spring:

    Application
        |
        +--> Create EntityManagerFactory
        +--> Create EntityManager
        +--> Begin transaction
        +--> Perform JPA operations
        +--> Commit transaction
        +--> Close resources

With Spring:

    Spring Container
        |
        +--> Configure EntityManagerFactory
        +--> Manage EntityManager integration
        +--> Manage transactions
        +--> Inject dependencies
        +--> Manage application lifecycle

- The actual JPA operations remain familiar.


------------------------------------------------------------
What Does NOT Change
------------------------------------------------------------

- The following remain JPA/Hibernate concepts:

  - Entities
  - @Entity
  - @Id
  - Relationships
  - @OneToMany
  - @ManyToOne
  - @ManyToMany
  - @OneToOne
  - Entity lifecycle
  - Persistence context
  - EntityManager
  - JPQL
  - Dirty checking
  - Lazy loading
  - Cascading
  - Fetch types
  - Optimistic locking
  - Pessimistic locking
  - Hibernate caching
  - Hibernate-specific features

- Spring does not redefine these concepts.
- Spring provides integration and management around them.



    JPA
      |
      +--> Standard persistence API/specification
      |
      +--> EntityManager
      +--> Entity lifecycle
      +--> Persistence context
      +--> JPQL
      +--> Mapping annotations

    Hibernate
      |
      +--> JPA implementation
      +--> SQL generation
      +--> Dirty checking implementation
      +--> Lazy loading implementation
      +--> Hibernate-specific features

    Spring
      |
      +--> Dependency injection
      +--> JPA infrastructure configuration
      +--> EntityManager integration
      +--> Transaction management
      +--> Application lifecycle
      +--> Integration with other Spring components


------------------------------------------------------------
Spring + JPA + Hibernate Application Flow
------------------------------------------------------------

Example:

    @Service
    public class UserService {

        @PersistenceContext
        private EntityManager entityManager;

        @Transactional
        public void createUser(User user) {
            entityManager.persist(user);
        }
    }

Flow:

    Client
       |
       v
    Controller
       |
       v
    Service
       |
       | @Transactional
       v
    Spring Transaction Management
       |
       v
    EntityManager
       |
       v
    Persistence Context
       |
       v
    Hibernate
       |
       v
    Database
