=======================================================================================================================================================================
									SPRING BOOT — DATA JPA
=======================================================================================================================================================================
=======================================================================================================================================================================

- Spring Boot simplifies the setup of a Spring Data JPA application by automatically configuring the infrastructure required to connect the application to a database and use JPA repositories.

- The main components involved are:

    DataSource
        ↓
    EntityManagerFactory
        ↓
    JpaTransactionManager
        ↓
    Spring Data JPA Repositories

- Boot creates and wires these components based on:
  - Dependencies available on the classpath
  - Application configuration
  - Existing beans
  - Database driver
  - JPA provider


------------------------------------------------------------
Creating a Spring Data JPA Application
------------------------------------------------------------

- A typical Spring Boot Data JPA application includes:

    spring-boot-starter-data-jpa

- This starter provides the dependencies required for Spring Data JPA and JPA/Hibernate integration.

Conceptually:

    spring-boot-starter-data-jpa
              |
              +--> Spring Data JPA
              +--> Spring ORM / JPA support
              +--> Hibernate
              +--> Transaction support
              +--> Required supporting dependencies


------------------------------------------------------------
Database Driver
------------------------------------------------------------

- The database JDBC driver must also be available.

Example for PostgreSQL:

    org.postgresql:postgresql

Example for MySQL:

    com.mysql:mysql-connector-j

- The driver allows the DataSource to communicate with the selected database.
- The database driver is normally added separately from spring-boot-starter-data-jpa because the application chooses its database.


------------------------------------------------------------
Spring Boot Application Startup
------------------------------------------------------------

Example:

    @SpringBootApplication
    public class Application {

        public static void main(String[] args) {

            SpringApplication.run(
                Application.class,
                args
            );
        }
    }

- During startup, Boot:
  - Creates the application environment.
  - Creates the ApplicationContext.
  - Performs component scanning.
  - Applies DataSource auto-configuration.
  - Applies JPA/Hibernate auto-configuration.
  - Configures repository infrastructure.
  - Configures transaction management.
  - Creates the required beans.

- The result is a Spring ApplicationContext containing the database and persistence infrastructure required by the application.


=======================================================================================================================================================================
DataSource Auto-Configuration
=======================================================================================================================================================================

------------------------------------------------------------
DataSource Auto-Configuration
------------------------------------------------------------

- Spring Boot automatically configures a DataSource when the required JDBC/database dependencies and configuration are available.
- The DataSource becomes the application's entry point for obtaining database connections.

Conceptually:

    Database Driver
          +
    Database Properties
          |
          v
    DataSource Auto-Configuration
          |
          v
       DataSource


------------------------------------------------------------
JDBC Driver Detection
------------------------------------------------------------

- Boot can determine the appropriate JDBC setup from the database driver available on the classpath.
- The driver must still be supplied by the application.

Example:

    PostgreSQL driver
          +
    PostgreSQL JDBC URL
          |
          v
    PostgreSQL DataSource


------------------------------------------------------------
Database Connection Properties
------------------------------------------------------------

- Database connection details are normally configured using Boot properties.

Example:

    spring.datasource.url=jdbc:postgresql://localhost:5432/appdb
    spring.datasource.username=app
    spring.datasource.password=secret

- The common properties are:

    spring.datasource.url
    spring.datasource.username
    spring.datasource.password
    spring.datasource.driver-class-name


------------------------------------------------------------
DataSource Configuration
------------------------------------------------------------

- Boot uses these properties to create and configure the DataSource.
- Boot also supports connection-pool configuration when a supported connection pool is available.

Example:

    spring.datasource.hikari.maximum-pool-size=10

- The exact pool-specific properties depend on the DataSource implementation being used.


------------------------------------------------------------
DataSource Auto-Configuration Conditions
------------------------------------------------------------

- DataSource auto-configuration is conditional.
- Boot considers factors such as:
  - Required JDBC classes
  - Database driver availability
  - Database configuration
  - Whether a DataSource bean already exists

- If the application provides its own DataSource, Boot's default DataSource auto-configuration can back off where the auto-configuration is conditional on a missing DataSource.


=======================================================================================================================================================================
JPA and Hibernate Auto-Configuration
=======================================================================================================================================================================

------------------------------------------------------------
JPA Auto-Configuration
------------------------------------------------------------

- Once a suitable DataSource and JPA-related dependencies are available, Spring Boot can automatically configure JPA infrastructure.

Conceptually:

    DataSource
        +
    JPA dependencies
        |
        v
    JPA Auto-Configuration
        |
        +--> EntityManagerFactory
        +--> JPA provider configuration
        +--> JPA integration


------------------------------------------------------------
Hibernate as the Default JPA Provider
------------------------------------------------------------

- spring-boot-starter-data-jpa includes Hibernate as the default JPA provider.
- Therefore, a typical Boot Data JPA application uses:

    JPA
      ↓
    Hibernate
      ↓
    Database

- JPA remains the persistence API/specification.
- Hibernate provides the implementation.


------------------------------------------------------------
EntityManagerFactory Auto-Configuration
------------------------------------------------------------

- Boot automatically configures an EntityManagerFactory for the application.
- The EntityManagerFactory is responsible for creating EntityManager instances.

Conceptually:

    DataSource
        +
    JPA/Hibernate configuration
        |
        v
    EntityManagerFactory
        |
        v
    EntityManager


------------------------------------------------------------
Persistence Unit in Spring Boot
------------------------------------------------------------

- In a traditional JPA application, the persistence unit is explicitly described in persistence.xml.
- In a Spring Boot application, persistence.xml is normally not required.

Traditional JPA:

    persistence.xml
          |
          +--> Persistence unit
          +--> Provider
          +--> DataSource/configuration
          +--> Persistence settings


Spring Boot:

    application.properties
          +
    Boot auto-configuration
          +
    Entity scanning
          +
    Hibernate configuration
          |
          v
    EntityManagerFactory
          |
          v
    Persistence unit configuration


- Boot constructs the required JPA persistence infrastructure programmatically.
- Therefore, there is normally no need to create persistence.xml manually.


------------------------------------------------------------
Entity Scanning
------------------------------------------------------------

- Boot automatically discovers JPA entities in the application's entity packages.
- The default scanning is based on the package structure of the main application class.

Example:

    com.example
        |
        +-- Application.java
        |
        +-- entity
        |     +-- User.java
        |
        +-- repository
        |     +-- UserRepository.java

- When Application is in the root package, Boot can automatically discover User as a JPA entity.


------------------------------------------------------------
JPA and Hibernate Properties
------------------------------------------------------------

- JPA and Hibernate behavior can be configured using Boot properties.

Examples:

    spring.jpa.show-sql=true

    spring.jpa.hibernate.ddl-auto=update

    spring.jpa.properties.hibernate.format_sql=true

- Boot uses these properties when constructing the JPA/Hibernate infrastructure.


=======================================================================================================================================================================
Spring Data JPA Repository Auto-Configuration
=======================================================================================================================================================================

------------------------------------------------------------
Repository Detection
------------------------------------------------------------

- Boot automatically detects Spring Data JPA repository interfaces.
- The repositories become Spring beans that can be injected into application components.

Example:

    public interface UserRepository
            extends JpaRepository<User, Long> {
    }

- No manual repository bean implementation is required.


------------------------------------------------------------
Repository Package Scanning
------------------------------------------------------------

- Boot automatically scans for repository interfaces in the application's repository packages.
- The default package is determined from the main application configuration.

Example:

    com.example
        |
        +-- Application.java
        |
        +-- repository
              |
              +-- UserRepository.java

- UserRepository is automatically discovered and registered.


------------------------------------------------------------
Repository Proxy Creation
------------------------------------------------------------

- Spring Data JPA creates the repository implementation dynamically.
- Boot's role is to automatically configure the Spring Data JPA repository infrastructure.

Conceptually:

    UserRepository interface
            |
            v
    Spring Data JPA
            |
            v
    Repository Proxy
            |
            v
    EntityManager
            |
            v
    Database


------------------------------------------------------------
Default Repository Configuration
------------------------------------------------------------

- For the normal application structure, Boot configures repository infrastructure automatically.
- Developers therefore do not normally need to add @EnableJpaRepositories.


------------------------------------------------------------
@EnableJpaRepositories
------------------------------------------------------------

- @EnableJpaRepositories explicitly enables and configures Spring Data JPA repositories.
- It becomes useful when the default repository scanning/configuration is insufficient.

Example:

    @EnableJpaRepositories(
        basePackages = "com.example.repositories"
    )

- In a normal Boot application, this is usually unnecessary because Boot performs repository auto-configuration.


------------------------------------------------------------
Custom Repository Configuration
------------------------------------------------------------

- Repository scanning can be customized when repositories are located outside the default package structure.

Example:

    @EnableJpaRepositories(
        basePackages = {
            "com.example.user.repositories",
            "com.example.order.repositories"
        }
    )

- Explicit configuration should be used only when the default Boot configuration does not match the application's package structure or requirements.


=======================================================================================================================================================================
Transaction Management Auto-Configuration
=======================================================================================================================================================================

------------------------------------------------------------
JpaTransactionManager Auto-Configuration
------------------------------------------------------------

- Spring Boot automatically configures a JpaTransactionManager for a typical single-database JPA application.

Conceptually:

    EntityManagerFactory
            |
            v
    JpaTransactionManager
            |
            v
       Transactions


------------------------------------------------------------
@EnableTransactionManagement
------------------------------------------------------------

- @EnableTransactionManagement enables Spring's annotation-driven transaction management.

- In a typical Spring Boot application, transaction management is auto-configured, so explicit @EnableTransactionManagement is generally unnecessary.

- The application can therefore directly use @Transactional.


------------------------------------------------------------
@Transactional
------------------------------------------------------------

Example:

    @Service
    public class UserService {

        @Transactional
        public void createUser(User user) {

            userRepository.save(user);
        }
    }

- Boot provides the transaction infrastructure required for @Transactional to work in the normal JPA setup.
- The actual transaction semantics belong to Spring's transaction management and JPA, not to Spring Boot.


------------------------------------------------------------
Transaction Manager Customization
------------------------------------------------------------

- If an application requires a different transaction configuration, the transaction manager can be explicitly configured.

- This is particularly relevant when an application contains:
  - Multiple DataSources
  - Multiple persistence units
  - Multiple transaction managers
  - Non-standard transaction requirements

- A custom transaction manager can cause the relevant Boot auto-configuration to back off where applicable.


=======================================================================================================================================================================
Database Initialization
=======================================================================================================================================================================

------------------------------------------------------------
Hibernate Schema Generation
------------------------------------------------------------

- Hibernate can create, update, validate, or recreate database schema structures according to the configured strategy.

The Boot property is:

    spring.jpa.hibernate.ddl-auto

Common values:

    none
    validate
    update
    create
    create-drop

Example:

    spring.jpa.hibernate.ddl-auto=update

- The appropriate value depends on the application's environment and schema-management strategy.


------------------------------------------------------------
schema.sql
------------------------------------------------------------

- Spring Boot can execute SQL initialization scripts such as schema.sql.

Example:

    src/main/resources/schema.sql

- This can be used to explicitly define database schema creation statements.


------------------------------------------------------------
data.sql
------------------------------------------------------------

- Spring Boot can execute data.sql to insert initial data.

Example:

    src/main/resources/data.sql

Example content:

    INSERT INTO users(id, name)
    VALUES (1, 'Sai');


------------------------------------------------------------
Initialization Ordering
------------------------------------------------------------

- Database initialization can involve both Hibernate schema generation and SQL scripts.
- Their interaction must be configured appropriately when both mechanisms are used.

- A common development setup may use Hibernate to create the schema and data.sql to populate initial data.


------------------------------------------------------------
Development vs Production
------------------------------------------------------------

- Automatic schema modification is convenient during development.
- Production databases are generally managed using controlled database migration tools rather than allowing Hibernate to modify the production schema automatically.

- Therefore, settings such as:

    spring.jpa.hibernate.ddl-auto=update

should not be treated as a general production database-management strategy.


=======================================================================================================================================================================
Spring Boot JPA Configuration Properties
=======================================================================================================================================================================

------------------------------------------------------------
spring.datasource.*
------------------------------------------------------------

- Configures the DataSource and database connection.

Important properties include:

    spring.datasource.url
    spring.datasource.username
    spring.datasource.password
    spring.datasource.driver-class-name

Example:

    spring.datasource.url=jdbc:postgresql://localhost:5432/appdb
    spring.datasource.username=app
    spring.datasource.password=secret


------------------------------------------------------------
spring.jpa.*
------------------------------------------------------------

- Configures general JPA behavior.

Examples:

    spring.jpa.show-sql=true

    spring.jpa.open-in-view=false


------------------------------------------------------------
spring.jpa.hibernate.*
------------------------------------------------------------

- Configures Hibernate-specific behavior exposed through Boot.

Example:

    spring.jpa.hibernate.ddl-auto=validate


------------------------------------------------------------
spring.jpa.properties.*
------------------------------------------------------------

- Allows provider-specific JPA properties to be passed to the JPA provider.

Example:

    spring.jpa.properties.hibernate.format_sql=true

    spring.jpa.properties.hibernate.jdbc.batch_size=50

- The exact properties under this namespace depend on the JPA provider.


------------------------------------------------------------
Common Configuration Categories
------------------------------------------------------------

    spring.datasource.*
        → Database connection / DataSource

    spring.jpa.*
        → General JPA configuration

    spring.jpa.hibernate.*
        → Hibernate-specific Boot configuration

    spring.jpa.properties.*
        → Provider-specific properties


------------------------------------------------------------
Development vs Production Configuration
------------------------------------------------------------

- Configuration can be externalized using the normal Spring Boot configuration mechanism.

Example:

    application.properties
    application-dev.properties
    application-prod.properties

- This allows database configuration to change between environments without changing application code.


=======================================================================================================================================================================
JPA / Hibernate Customization in Spring Boot
=======================================================================================================================================================================

------------------------------------------------------------
Custom DataSource Configuration
------------------------------------------------------------

- Boot's automatically configured DataSource can be replaced or customized when the application has special requirements.

Example:

    @Bean
    public DataSource dataSource() {
        ...
    }

- Typical reasons include:
  - Custom connection pool
  - Multiple DataSources
  - Special connection configuration
  - Custom DataSource implementation


------------------------------------------------------------
Custom EntityManagerFactory Configuration
------------------------------------------------------------

- Boot normally creates the EntityManagerFactory automatically.
- It can be explicitly configured when the application needs a non-standard JPA setup.

Typical reasons include:

    Multiple persistence units
    Multiple DataSources
    Custom entity packages
    Provider-specific configuration
    Advanced JPA setup

- When taking over this configuration, the application becomes responsible for configuring the required JPA infrastructure correctly.


------------------------------------------------------------
Custom Hibernate / JPA Properties
------------------------------------------------------------

- Provider-specific settings can often be supplied without replacing the entire EntityManagerFactory configuration.

Example:

    spring.jpa.properties.hibernate.format_sql=true

- This is preferable when only a provider-specific setting needs to change.


------------------------------------------------------------
Custom Transaction Manager
------------------------------------------------------------

- A custom transaction manager can be defined when the default JpaTransactionManager does not meet the application's requirements.

Example:

    @Bean
    public PlatformTransactionManager transactionManager(
            EntityManagerFactory emf) {

        return new JpaTransactionManager(emf);
    }


------------------------------------------------------------
Auto-Configuration Back-Off
------------------------------------------------------------

- Boot's auto-configuration is designed to back off when the application explicitly provides configuration for the relevant infrastructure.

Conceptually:

    Boot
      |
      +--> DataSource
      +--> EntityManagerFactory
      +--> TransactionManager
      |
      v
    Application provides custom bean?
          |
       Yes
          |
          v
    Relevant Boot auto-configuration
    backs off where applicable

- Providing one custom bean does not automatically disable all Data JPA auto-configuration.


=======================================================================================================================================================================
Entity and Repository Configuration
=======================================================================================================================================================================

------------------------------------------------------------
Default Package Structure
------------------------------------------------------------

- Boot uses the package containing the main @SpringBootApplication class as the default reference point for component and persistence scanning.

Example:

    com.example
        |
        +-- Application.java
        |
        +-- entity/
        +-- repository/
        +-- service/


- This structure allows Boot to discover the application's components, entities, and repositories automatically.


------------------------------------------------------------
Custom Entity Scanning
------------------------------------------------------------

- Entity scanning can be customized when entities are outside the default package structure.

Example:

    @EntityScan("com.example.entities")
    @SpringBootApplication
    public class Application {
        ...
    }

- @EntityScan changes where Boot looks for JPA entities.


------------------------------------------------------------
Custom Repository Scanning
------------------------------------------------------------

- Repository scanning can be customized when repositories are outside the default package structure.

Example:

    @EnableJpaRepositories(
        basePackages = "com.example.repositories"
    )

- This explicitly identifies the repository packages.


------------------------------------------------------------
Custom Base Packages
------------------------------------------------------------

- Custom scanning should be used when the application's package structure does not naturally fall under the main application package.

Example:

    com.example.app
        |
        +-- Application.java

    com.example.persistence
        |
        +-- entity/
        +-- repository/

- If persistence components are outside the default scanning structure, explicit scanning configuration may be required.


------------------------------------------------------------
Package Configuration Principle
------------------------------------------------------------

- The simplest Boot configuration is achieved by placing the main application class at the root of the application's package hierarchy.

Example:

    com.example
        |
        +-- Application.java
        |
        +-- controller/
        +-- service/
        +-- repository/
        +-- entity/

- This allows Boot's default scanning behavior to cover the application without additional package configuration.


=======================================================================================================================================================================
Spring Boot Data JPA Auto-Configuration Flow
=======================================================================================================================================================================

------------------------------------------------------------
Complete Configuration Flow
------------------------------------------------------------

A typical Boot Data JPA application starts approximately as follows:

    @SpringBootApplication
            |
            v
    SpringApplication.run()
            |
            v
    ApplicationContext
            |
            v
    Component Scanning
            |
            +-----------------------------+
            |                             |
            v                             v
    DataSource Auto-Config        Data JPA Auto-Config
            |                             |
            v                             v
       DataSource                 EntityManagerFactory
            |                             |
            +-------------+---------------+
                          |
                          v
                JpaTransactionManager
                          |
                          v
             Repository Auto-Configuration
                          |
                          v
                  Repository Proxies
                          |
                          v
                    Application


------------------------------------------------------------
DataSource
------------------------------------------------------------

- The DataSource represents the database connection infrastructure.
- Boot creates it using the configured database properties and available JDBC infrastructure.


------------------------------------------------------------
EntityManagerFactory
------------------------------------------------------------

- Boot uses the DataSource and JPA/Hibernate configuration to create the EntityManagerFactory.
- Hibernate is normally the JPA provider.


------------------------------------------------------------
TransactionManager
------------------------------------------------------------

- Boot configures JpaTransactionManager using the JPA persistence infrastructure.
- It enables Spring's transaction abstraction to work with JPA.


------------------------------------------------------------
Repository Infrastructure
------------------------------------------------------------

- Boot configures Spring Data JPA repository infrastructure.
- Repository interfaces are discovered and corresponding proxy implementations are created.


------------------------------------------------------------
ApplicationContext Integration
------------------------------------------------------------

The resulting ApplicationContext contains infrastructure such as:

    DataSource
    EntityManagerFactory
    JpaTransactionManager
    Repository proxies
    Application services
    Other application beans

- These components are managed together by Spring's IoC container.


=======================================================================================================================================================================
Production Configuration
=======================================================================================================================================================================

------------------------------------------------------------
Externalized Database Configuration
------------------------------------------------------------

- Database credentials and connection details should normally be supplied through external configuration rather than hard-coded in Java source code.

Examples:

    Environment variables
    External configuration
    Deployment secrets
    Profile-specific configuration


------------------------------------------------------------
Profile-Specific Database Configuration
------------------------------------------------------------

Example:

    application-dev.properties

    spring.datasource.url=jdbc:postgresql://localhost:5432/devdb


    application-prod.properties

    spring.datasource.url=jdbc:postgresql://prod-server:5432/proddb

- The same application artifact can therefore use different databases depending on the active profile.


------------------------------------------------------------
Connection Pool Configuration
------------------------------------------------------------

- Production applications normally use a connection pool rather than creating a new physical database connection for every operation.
- Spring Boot commonly configures HikariCP when it is available.

Example:

    spring.datasource.hikari.maximum-pool-size=20
    spring.datasource.hikari.minimum-idle=5

- Pool settings should be chosen according to application workload and database capacity.


------------------------------------------------------------
Schema Management Strategy
------------------------------------------------------------

- Production schema changes should generally be controlled through database migration tooling rather than relying on Hibernate's automatic schema modification.

Typical approach:

    Application
        |
        +--> JPA/Hibernate
        |
        +--> Database migration tool
        |
        v
    Production Database


------------------------------------------------------------
Actuator Database Health
------------------------------------------------------------

- Spring Boot Actuator can provide health information for database connectivity when the relevant health indicators are available.

Example:

    /actuator/health

- This allows deployment and monitoring systems to determine whether the application's database dependency is healthy.
