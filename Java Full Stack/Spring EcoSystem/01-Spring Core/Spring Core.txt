=============================================================================================================================================================================
Spring
=============================================================================================================================================================================

Goal:
Achieve Loose Coupling between components using Dependency Injection (DI).

Spring did NOT invent Dependency Injection.
Dependency Injection already existed in Plain Java.

Spring simply automates Dependency Injection and Bean Lifecycle Management.

=============================================================================================================================================================================
What is a Dependency? and why Dependency Injection is Important?
=============================================================================================================================================================================

A dependency is an object that another object needs to perform its work.

Example:

UserService
      │
      ▼
UserRepository
      │
      ▼
Database


Here,
- UserRepository is a dependency of UserService.
- Database is a dependency of UserRepository.

=============================================================================================================================================================================

Without DI (Tight Coupling), every class creates its own dependencies:

class Engine {
    void start() {
        System.out.println("Engine Started");
    }
}

class Car {
    private Engine engine;
    public Car() {
        // Car creates its own dependency
        engine = new Engine();

    }
    public void drive() {

        engine.start();
        System.out.println("Driving...");
    }
}


Problems:

- Car is tightly coupled with Engine.
- Replacing Engine with ElectricEngine requires modifying Car.
- Testing becomes difficult because Engine cannot be replaced with a FakeEngine.
- Car has two responsibilities:
	- Driving
	- Creating Engine

This violates the Single Responsibility Principle (SRP) from SOLID.

=============================================================================================================================================================================

With DI (Loose Coupling), instead of creating the dependency, receive it from outside:

interface Engine {
    void start();
}

class PetrolEngine implements Engine {
    public void start() {
        System.out.println("Petrol Engine Started");
    }
}

class ElectricEngine implements Engine {
    public void start() {
        System.out.println("Electric Engine Started");
    }
}

class Car {
    private Engine engine;
    public Car(Engine engine) {
        this.engine = engine;
    }
    public void drive() {
        engine.start();
        System.out.println("Driving...");
    }
}



Plugging:
Engine engine = new PetrolEngine();
Car car = new Car(engine);
car.drive();


Unplugging (change):
Engine engine = new ElectricEngine();
Car car = new Car(engine);
car.drive();


Now,
Plugging and unplugging require changing only the Main class.
The Car class remains unchanged.
This is called Loose Coupling.


Here, we achieved DI with plain Java (not Spring); Then why do we need Spring?

=============================================================================================================================================================================
Why Spring?
=============================================================================================================================================================================

Imagine an application with only 3 classes.

Database
    ↓
Repository
    ↓
Service

Easy to manage.


Now imagine an enterprise application.

Database
    ↓
100 Repositories
    ↓
150 Services
    ↓
50 Controllers
    ↓
Security
    ↓
Cache
    ↓
Messaging
    ↓
...


Now you have to manually:

- Create every object.
- Inject every dependency.
- Decide the order of creation.
- Manage singleton objects.
- Initialize resources.
- Destroy resources.

This quickly becomes difficult.

------------------------------------------------------------
Spring's Solution


Instead of writing:

Database database = new Database();
Repository repository = new Repository(database);
Service service = new Service(repository);

You simply tell Spring (configure):

- Which classes are Beans.
- What dependencies they need.

Spring automatically:

1. Discovers Beans.
2. Creates BeanDefinitions.
3. Instantiates Beans.
4. Injects Dependencies.
5. Runs Bean Lifecycle.
6. Stores Beans in the IoC Container.
7. Destroys Beans when the application stops.

In short, Spring handles Dependency Injection (DI) and automates the bean lifecycle.

=============================================================================================================================================================================
What is Inversion of Control (IoC)?
=============================================================================================================================================================================

The control of object creation is transferred to Spring.
This principle is called Inversion of Control (IoC).

=============================================================================================================================================================================
IoC vs Dependency Injection
=============================================================================================================================================================================

Inversion of Control (IoC)

- A Design Principle.
- Means transferring the control of object creation and lifecycle management to another system.

------------------------------------------------------------

Dependency Injection (DI)

- A Design Technique.
- Means providing dependencies from outside instead of creating them inside the class.

------------------------------------------------------------

Relationship:

DI is the technique used to achieve IoC

=============================================================================================================================================================================
What is Spring IoC Container?
=============================================================================================================================================================================

The Spring IoC container is the core engine of the Spring Framework.
It acts as a centralized factory responsible for creating, configuring, wiring, and managing the entire lifecycle of application objects (known as Beans).

------------------------------------------------------------

Types: 

1. BeanFactory (The Core):
- The most basic container interface.
- Uses Lazy Loading (creates (instantiates and injects) objects only when you explicitly ask for them via getBean()).
- Ideal for lightweight applications like mobile devices or low-resource environments.

------------------------------------------------------------

2. ApplicationContext (The Advanced Standard):
- A direct subsystem of BeanFactory that includes all its features.
- Uses Eager Loading (creates all singleton objects immediately upon application startup).
- Adds enterprise features like internationalisation (i18n), event publishing, and seamless AOP (Aspect-Oriented Programming) integration.

All implementations of ApplicationContext Interface:
- ClassPathXmlApplicationContext		- for Standalone Java	- XML file on Classpath
- FileSystemXmlApplicationContext		- for Standalone Java	- XML file on Local disk
- XmlWebApplicationContext			- for Web Application	- XML file under web folder
- AnnotationConfigApplicationContext		- for Standalone Java	- @Configuration Classes / Scans
- AnnotationConfigWebApplicationContext		- for Web Application	- @Configuration Classes


=============================================================================================================================================================================
What is Spring Configuration?
=============================================================================================================================================================================

In Spring framework, configuration refers to the blueprint, setup instructions, and metadata that tell the Spring IoC (Inversion of Control) container how to instantiate, assemble, and manage application objects (called Beans)

Every new version of Spring reduced the amount of configuration required while keeping the same IoC Container and Dependency Injection mechanism.

Dependency Injection:



Constructor injection:
	- <constructor-arg ref="beanRef">
	- The Spring container inspects the target class to find a constructor whose parameter types and order match the provided arguments. It instantiates the bean and injects the dependencies simultaneously during object creation, throwing an ambiguous constructor error if multiple matches exist.




Setter injection:	
	- <property name="propertyNameThatMatchesTheSetterMethod" ref="beanRef">
	- The Spring container converts the name attribute value to match Java Bean naming conventions. It capitalizes the first letter of the name, prefixes it with "set", and looks for that exact method (e.g., engine becomes setEngine). If the method name does not match this convention, Spring throws a BeanCreationException




Autowiring:
	- While Constructor and Setter injections are the manual configurations for wiring (injection), because we are explicitly instructing which bean to inject using <constructor-arg> and <property> tags, XML autowiring tells the Spring container to look at your Java classes and automatically figure out dependencies. This eliminates the need to explicitly write <property> or <constructor-arg> tags.
	- Autowire byName: When you set autowire="byName", Spring looks at the setter method name (or property field name) in your class. It then searches the XML file for a <bean> with an id that matches exactly. 

	Example: 
	public class Car {
    		private Engine subaruEngine; // Field name
    
    		// Spring looks for a bean id matching this property name: "subaruEngine"
    		public void setSubaruEngine(Engine engine) { 
        		this.subaruEngine = engine; 
    		}
	}

	<!-- The ID matches the setter property name perfectly -->
	<bean id="subaruEngine" class="com.example.Engine" />

	<!-- No <property> tag needed -->
	<bean id="myCar" class="com.example.Car" autowire="byName" />


	- Autowire byType: When you set autowire="byType", Spring ignores the bean IDs. Instead, it looks at the data type required by the setter method and searches the XML file for a bean of that exact class or interface type. If multiple beans of same type are there, use primary = "true"
	
	Example:
	public class Car {
    		private Engine engine;
    
    		// Spring looks for any bean in the XML that is an instance of "Engine"
    		public void setEngine(Engine engine) { 
        		this.engine = engine; 
    		}
	}

	<!-- The ID does not matter; only the class type matters -->
	<bean id="anyRandomId" class="com.example.Engine" />

	<!-- No <property> tag needed -->
	<bean id="myCar" class="com.example.Car" autowire="byType" />


	- Note: autowiring only works with setter methods


------------------------------------------------------------

Plugging and Unplugging:

Constructor or Setter Injection	: Replace the bean reference in constructor-arg/property tag with the target bean reference
Autowire byName			: Change the ID of your target bean in the XML file to match the setter method name/field name of the host class
Autowire byType			: When you have multiple beans with matching type, place the primary="true" in the target bean tag

Dependency Injection:

- With annotation-based configuration, Spring automatically discovers the required beans and injects them.
- Unlike XML configuration, you do not manually specify the wiring using <constructor-arg> or <property>. Instead, Spring determines the dependencies from your classes (using constructors, setters, or @Autowired).
- Types: Field injection, Constructor injection (recommended) and Setter injection
- By default, every Spring bean created using @Component, @Service, @Repository or @Controller is assigned a bean name
- The default bean name is the class name with the first letter in lowercase. Example: UserService -> userService, DatabaseConnection -> databaseConnection
- By default @Autowired performs Dependency Injection by TYPE.

Example:

@Autowired
private Database database;

Spring looks for a bean whose type is Database.


- Case 1: Only one bean of type Database exists ---> Spring injects it automatically
- Case 2: Multiple beans of type Database exist ---> If one bean is marked with @Primary, Spring injects that bean.
- Case 3: If no @Primary exists ---> you can specify the required bean using @Qualifier

Example:

@Autowired
@Qualifier("oracleDatabase")
private Database database;

Spring injects the bean whose name is "oracleDatabase".


- Case 4: If multiple beans exist and neither @Primary nor @Qualifier is provided ---> Spring throws: NoUniqueBeanDefinitionException
- @Primary is placed on the Bean; @Qualifier is placed where the dependency is injected.

------------------------------------------------------------

Plugging and Unplugging:


Constructor Injection    : Replace the implementation passed to the constructor, or mark the required implementation with @Primary / specify it using @Qualifier.
Setter Injection         : Replace the implementation passed to the setter, or mark the required implementation with @Primary / specify it using @Qualifier.
Field Injection          : Mark the required implementation with @Primary or specify it using @Qualifier.
@Primary                 : Place @Primary on the preferred bean implementation.
@Qualifier               : Place @Qualifier("beanName") at the injection point to inject a specific bean.

Spring 3.x introduced Java-based configuration as an alternative to XML. Bean Configuration:

- @Configuration
- @Bean
- @ComponentScan


public class UserService {

    private UserRepository repository;

    public UserService(UserRepository repository) {
        this.repository = repository;
    }
}

public class UserRepository {

    private Database database;

    public UserRepository(Database database) {
        this.database = database;
    }
}

public class Database {
}

@Configuration
public class AppConfig {

    @Bean
    public Database database() {
        return new Database();
    }

    @Bean
    public UserRepository repository() {
        return new UserRepository(database());
    }

    @Bean
    public UserService service() {
	return new UserService(repository());
    }
}
