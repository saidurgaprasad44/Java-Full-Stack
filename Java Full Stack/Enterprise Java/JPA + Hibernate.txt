JPA/Hibernate  (Automated Mapping & SQL)
=======================================================================================================================================================================

Database Connection: Automated (Hibernate uses its own built-in connection pool or hooks into one you provide)
Object-to-Table Mapping: Automated (Done via @Entity and @Column annotations)
SQL Writing: Automated (You call session.save(user) and Hibernate writes the INSERT INTO... SQL statement for you)

=======================================================================================================================================================================

Hibernate has its own API specification before the standard JPA API was introduced.
Later when JPA API was introduced, it has all the standard persistence specifications using which JPA/Hibernate was implemented again.

EntityManager and Persistence operations 

EntityManager is an interface used to manage the entities and its lifecyle in the persistence context

- em.persist(employee) - CREATE: creates new entity in persistence context to manage/track it and schedule it to be inserted in the db
- em.find() - READ: JPA first checks the persistence context, return it if it is present in persistence context, or query database, create entity in persistence context, & make it managed 
- em.remove(employee) - DELETE: mark it for deletion and during flush, hibernate removes it 
- merge():  
- em.flush():
- em.detach(): 
- em.clear():
- em.close(): closes the entitymanager/persistence context
