------------------------------------------------------------
String: 
------------------------------------------------------------

- Immutable, so its contents cannot be changed after creation, any change will create a completely new object in string pool, so automatically thread-safe.

- String Literal: 
	- Example: String str = "Java"; // Declared and initialized using a literal
	- The most common way. It uses the String Pool for memory efficiency.
	- If "Java" already exists in the pool, the new reference points to the existing object.

- Using the new Keyword: 
	- Example: String s = new String("Java"); // Explicit instantiation
	- This forces the creation of a new object in the standard heap memory, even if "Java" already exists in the pool.
	- Less efficient; creates redundant objects.

- Example: 
	String s1 = "Hello";
	String s2 = "Hello";
	String s3 = new String("Hello");
	System.out.println(s1 == s2); // true (same reference in pool)
	System.out.println(s1 == s3); // false (different objects in memory)
	System.out.println(sq.equals(s3) // true (== to compare the reference, while .equals() to compare the content)

------------------------------------------------------------
StringBuilder & StringBuffer:
------------------------------------------------------------

StringBuilder: Mutable, not synchronized, not thread-safe; ideal for local string construction
StringBuffer: Mutable, synchronized, thread-safe; useful in some shared-buffer scenarios, but not a universal concurrency solution because Synchronization adds overhead

- StringBuilder and StringBuffer have almost the same APIs. But internally StringBuffer methods are synchronized while StringBuilder methods are not.

- ASCII value: ASCII is an older character encoding standard defining 128 values, from 0 through 127. It includes English letters, digits, punctuation and control characters.

- Unicode code point: A number identifying a Unicode character, such as A or 😀.
- Visible character: What a user perceives as one character on screen. It may consist of multiple Unicode code points.

------------------------------------------------------------
Primitive Arrays: 
------------------------------------------------------------

- Stores raw data values (like 42 or true) directly in a contiguous memory block, initialized to type-specific defaults like 0 or false.

int[] n; // Declaration
int[] numbers = {40, 10, 30, 20}; 
int[] nums = new int[4];  // Instantiation

------------------------------------------------------------
Object Arrays:
------------------------------------------------------------

- Stores memory addresses (references) that point to objects elsewhere on the heap, initialized to null.

String[] names = new String[3];
Object[] objects = new Object[3];
Employee[] employees = new Employee[10];

------------------------------------------------------------
Multi-dimensional Arrays:
------------------------------------------------------------

- Array of arrays

int[][] matrix = {
    {1, 2, 3},
    {4, 5, 6}
};


Note:

- Once an array is instantiated, their size is fixed.
- When an array is instantiated, it will create an object of special internal type dynamically created (by JVM) Class with a name like  [I (for int[]) or [Ljava.lang.String; (for String[]).
- Use numbers.length, not numbers.length(), numbers.length is a property, not a method

------------------------------------------------------------
List (Ordered Sequence)
------------------------------------------------------------

- A List is an ordered collection that allows duplicate elements and provides index-based access. 
- Maintains the insertion order of elements.



Common Implementations:

ArrayList: 

- Best for fast random access and frequent searching by index.
- Understand the internals

List<Integer> nums = List.of(1, 34, 32, 45); //creates an unmodifiable List, cannot perform operations like set(), remove(), add(), ...
List<String> names = new ArrayList<>(List.of("sai", "vaishu", "bhuvana", "Priya", "Akshay")); //creates a modifiable ArrayList backed by arrays
List<String> roles = Arrays.toList("hr", "developer"); //creates a modifiable ArrayList from an object array


LinkedList: 

- Better for frequent insertions and deletions at the beginning or end.
- Understand the internals



Feature				ArrayList		LinkedList
--------------------------------------------------------------------------
Internal structure		Dynamic array		Doubly linked list
Index access			O(1)			O(n)
Append				Amortized O(1)		O(1)
Insert/remove at beginning	O(n)			O(1)
Insert/remove in middle		O(n)			O(n) to locate; O(1) to unlink
Memory overhead			Lower			Higher



Purpose		APIs								Detail to watch
---------------------------------------------------------------------------------------------------------------------------------------------
Add		add(), add(index, element), addAll()				Indexed insertion shifts subsequent elements in ArrayList.
Access		get(), indexOf(), lastIndexOf()					get() is O(1) for ArrayList, O(n) for LinkedList.
Update		set()								Replaces an element at an index.
Remove		remove(index), remove(object), removeAll(), retainAll()		remove(1) can mean remove index 1, not the Integer object 1.
Search		contains(), containsAll()					Usually O(n) for ArrayList.
Iterate		iterator(), listIterator(), forEach()				ListIterator supports bidirectional traversal and modification.
Extract		subList()							Returns a backed view, not an independent list.
Convert		toArray(), List.of()						List.of() creates an unmodifiable list and rejects nulls.



------------------------------------------------------------
Set (Unique Elements)
------------------------------------------------------------

- A Set is a collection that does not allow duplicate elements. 
- Used strictly when you need a collection of unique items.



Common Implementations:

HashSet: Most common; unordered and backed by a hash table for fast operations.
LinkedHashSet: Maintains the order in which elements were added.
TreeSet: Automatically keeps elements in a sorted order.



Feature			HashSet			LinkedHashSet			TreeSet
---------------------------------------------------------------------------------------------
Ordering		No guaranteed order	Insertion order			Sorted order
Internal structure	Hash table		Hash table + linked ordering	Balanced tree
Add/search/remove	O(1) average		O(1) average			O(log n)
Null			One null allowed	One null allowed		Generally no null with natural ordering
Duplicates		Not allowed		Not allowed			Not allowed



Purpose		APIs					Detail to watch
---------------------------------------------------------------------------------------------
Add		add(), addAll()				Returns false if the element already exists.
Remove		remove(), removeAll(), retainAll()	retainAll() keeps only common elements.
Search		contains(), containsAll()		HashSet uses hashCode and equals.
Size		size(), isEmpty()			Standard collection operations.
Convert		toArray()				Can convert the set into an array.
Iterate		iterator(), forEach()			HashSet iteration order is not guaranteed.



------------------------------------------------------------
Queue (Order of Processing)
------------------------------------------------------------

- A Queue is designed for holding elements prior to processing, typically following the FIFO (First-In-First-Out) principle. 
- Elements are added at the back and removed from the front.


Common Implementations:

PriorityQueue: Elements are ordered based on their natural priority or a custom comparator.
ArrayDeque: A double-ended queue that supports insertion and removal at both ends.


Hierarchy:

Collection(I) ------> Queue(I) ------> Deque(I) ------> ArrayDeque(C)
Collection(I) ------> Queue(I) ------> PriorityQueue(C)
Collection(I) ------> Deque(I) ------> LinkedList(C)


Syntax: 

Queue<Type> name = new LinkedList<>();

- List<Employee>
- Map<Integer, Employee>
- Set<Employee>



// Add objects
employees.add(new Employee(101, "John", "IT", 75000));
employees.add(new Employee(102, "Alice", "HR", 65000));

// Find an employee
Employee employee = employees.stream()
        .filter(e -> e.getId() == 101)
        .findFirst()
        .orElse(null);

// Create a lookup map using employee ID
Map<Integer, Employee> employeeById = employees.stream()
        .collect(Collectors.toMap(Employee::getId, Function.identity()));

// Group employees by department
Map<String, List<Employee>> byDepartment = employees.stream()
        .collect(Collectors.groupingBy(Employee::getDepartment));

Complexity fundamentals
=======================================================================================================================================================================

Learn enough Big-O notation to compare common operations:

O(1): constant-time operation
O(log n): logarithmic growth
O(n): linear traversal
O(n log n): common efficient sorting
O(n square): nested full-array comparisons

Typical costs for:
array access
list insertion
searching
hash lookups
sorting and
heap operations.

- These are typical or average costs in some cases, not guarantees for every operation.
- Which data structure suits a problem and why, before writing Java code.
